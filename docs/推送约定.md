# 推送约定（重要）

本仓库的**本地历史**与**对外仓库**是两套东西。改动代码后请按本文的流程推送，否则会把不该公开的东西带出去。

## 为什么不能直接 `git push`

本地早期提交（`52edccb`、`58b0618`）里曾经把真实的百度 OCR `API_KEY` / `SECRET_KEY` 写进 `legacy/python/config.py` 并提交。虽然后来的提交把值清空了，但**只要这段历史被推上去，凭据就永久可见** —— git 历史是可以逐条翻阅的。

因此：

- 本地保留完整历史（方便回溯、对比），**不直接推到任何人能看见的地方**；
- 对外仓库只接收「当前 HEAD 的干净快照」，历史被重建为单次初始化提交。

## 每次推送怎么做

```powershell
# 1. 先把改动提交到本地 main（本地怎么提交都行）
git add -A
git commit -m "fix: 修了 xxx"

# 2. 用脚本推送干净副本
pwsh scripts/push-clean.ps1 -Message "fix: 修了 xxx"

# 想先看看会不会泄露，不真的推：
pwsh scripts/push-clean.ps1 -DryRun
```

脚本会按顺序做这些事，任一步失败就中止：

| 步骤 | 作用 |
| :-- | :-- |
| 检查工作区 | 有未提交改动直接拒绝，避免推出去的和你以为的不一致 |
| `git worktree` 导出 HEAD | 只取已提交的内容，天然不含 `config.py` 这类被忽略的本机文件 |
| 敏感信息扫描 | 命中任一规则就中止并列出文件，规则见下节 |
| 检查 `config.py` | 意外出现在快照里也中止 |
| 全新单提交 + 强推 | 在临时目录 `git init`，用 GitHub noreply 作为作者，`--force` 推到 `org` 远端 |

## 扫描规则从哪来

规则分两类，**都不含真实值**，因为脚本本身是要公开的：

1. **结构规则**（写在 `scripts/push-clean.ps1` 里）：私有 IP 段、`API_KEY = "..."` 这类赋值形态、脚本里写死密码的形态。
2. **精确规则**（从本机 `scripts/sensitive.txt` 读取，该文件被 `.gitignore` 排除）：真实 AK/SK、学号、密码、姓名、会话票据。

首次使用：

```powershell
copy scripts\sensitive.example.txt scripts\sensitive.txt
# 编辑 scripts\sensitive.txt，一行一个真实值
```

> 为什么不把真实值直接写进脚本：脚本要公开，把 AK/SK 写在脚本里，脚本自己就成了泄露源。base64 也不是加密。

## 远端配置

```powershell
git remote -v
# origin  https://github.com/<你自己>/NXU_jwgl_auto_login.git        ← 个人仓库
# org     https://github.com/NingXia-XinQiCyberClub/nxu-jwgl-auto-login.git  ← 对外仓库，只走脚本
```

没有 `org` 时：

```powershell
git remote add org https://github.com/NingXia-XinQiCyberClub/nxu-jwgl-auto-login.git
```

## 需要你遵守的两条

1. **永远不要 `git push org`**，只用 `scripts/push-clean.ps1`。
2. **新增文件前想一下是否含真实信息**：验证码截图、导出的配置 JSON、日志、`config.py`、`chrome.storage` 备份都算。`.gitignore` 挡掉了常见几类，挡不住 `git add -f`。

## 如果已经误推了

顺序是**先作废凭据，再清理仓库**。删文件、改写历史只是「让后来的人看不到」，已经抓取过的副本收不回来。

- 百度 AK/SK → 到百度云控制台重新生成
- 学号密码 → 改密码
- 会话票据 / WebVPN 入口 → 该会话会过期，保险起见退出登录重进
