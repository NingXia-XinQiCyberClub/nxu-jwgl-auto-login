# NXU 教务系统自动登录（Chrome 扩展版）

## 项目简介

宁夏大学教务管理系统（<https://jwgl.nxu.edu.cn>）的自动登录 Chrome 扩展，提供两种工作方式：

- **后台静默登录（主力）**：在后台反复请求教务系统，一旦登录成功，立刻带着当前 Cookie 打开已登录的页面 —— 这就是原 Python 脚本的行为，适合抢课、蹲成绩这类「越早进系统越好」的场景。
- **页面自动填表**：打开登录页时，在页面里自动填好学号密码、识别验证码并提交，全程不离开你眼前这一页。

> 声明：本系统为开源软件，**禁止用以盈利！！！**

本项目由仓库里原有的 Python 脚本重构而来（原代码保留在 `legacy/python/`）。它解决的问题很具体：

| 原来的麻烦 | 现在的做法 |
| --- | --- |
| 得装 Python、装一堆库 | 只要一个 Chrome / Edge 浏览器 |
| 得改 `config.py` 里的源码常量 | 在扩展设置面板里填学号密码 |
| 得自己维护 `JSESSIONID`，还要保证「验证码和 session 是同一个」 | 请求与页面共用浏览器的 Cookie，会话天然一致 |
| 命令行里跑，登录完还得手动开浏览器 | 登录成功自动打开已登录页面 |

## 功能特性

### 后台静默登录

- **成功即开页面**：后台按你设定的间隔反复「取验证码 → 识别 → 提交登录」，一旦成功立刻新开标签页并直接落在登录后的页面上，不需要你再点。
- **校内外都能用**：入口地址支持两种写法 —— 校外走 WebVPN（`https://webvpn.nxu.edu.cn/https-443/<hex>/index.action`），校内直接写 `https://jwgl.nxu.edu.cn`。扩展会自动从入口推导出验证码和登录接口地址，WebVPN 那串 hex 前缀会原样保留。
- **验证码错误无限重试**：站点回「验证码不对」只当作一次普通失败，继续换图重试，直到达到你设定的次数上限。
- **密码错误立刻停**：站点回「账户不存在 / 密码错误」时立即停止并提示，避免拿着错密码反复刷号把账号刷锁。
- **识别不出就不提交**：OCR 只认出 1 个字母这类明显残废的结果，直接换一张验证码，不浪费一次登录请求。
- **浏览器启动自动开始**：可选「开机后自动开始」，开机即进入抢跑状态。

### 页面自动填表

- **页面内自动填表提交**：识别登录页的学号 / 密码 / 验证码输入框，像用户一样输入并提交，不需要任何服务端请求伪造。
- **验证码三种方案**（三选一，对应设置里的「识别服务」）：
  - `manual` 人工输入 —— 悬浮面板里直接看图输码，最稳；
  - `baidu` 百度智能云 OCR —— 用自己的 API Key / Secret Key；
  - `remote` 自建 OCR 服务 —— 自己部署的 ddddocr 之类接口。
  - 识别服务之外还有一个「验证码处理模式」：`auto`（默认，先试 OCR）和 `manual`（始终人工）。只有 `auto` + 非 `manual` 的识别服务才会调 OCR，识别失败会自动回退到人工输入。**后台静默登录只能用 OCR，不支持人工输入。**
- **多服务器地址**：可配置多个教务系统地址（含校内备用 IP）。除了默认站点，其余地址会由扩展动态注册页面脚本，并弹出一次访问权限询问；你打开哪个地址，就在哪个地址上自动登录。
- **失败自动重试**：可设置最多尝试次数（1–20，默认 5）与两次尝试的间隔（毫秒，默认 1200），每次失败自动换一张验证码，整页刷新后还能接着上次的次数继续。
- **成功后系统通知**：登录成功时发一条系统通知，切到别的窗口也能知道。
- **密码只存本机**：学号密码保存在 `chrome.storage.local`，不上传任何服务器。
- **状态悬浮面板**：页面右上角常驻小卡片，显示当前状态、第几次尝试、最近动态日志；就在面板里输验证码、取消或重试。
- **调试日志**：开启调试模式后，控制台与面板都会输出更详细的过程信息。
- **导入 / 导出配置**：设置可导出成 JSON 备份，默认**脱敏**（抹掉密码与百度密钥），也可显式导出完整版；导入后预览表单、点保存才生效。
- **清除状态**：弹窗里一键清空运行状态与日志（不动设置），卡在奇怪的中间状态时用来复位。

## 安装

要求 **Chrome 102 或更高版本**（扩展使用 MV3 + `chrome.scripting`）。

1. 打开 Chrome，地址栏输入 `chrome://extensions` 回车；
2. 打开右上角的 **「开发者模式」** 开关；
3. 点击左上角 **「加载已解压的扩展程序」**；
4. 在弹出的目录选择框里，选中本仓库里的 **`extension`** 目录（注意是 `extension` 这一层，不是仓库根目录）；
5. 列表里出现「NXU 教务系统自动登录」即安装完成。建议点一下扩展栏的图钉，把它固定到工具栏。

**Edge 用户**：路径完全等价，把第 1 步换成 `edge://extensions`，其余步骤（开发者模式 → 加载解压缩的扩展 → 选择 `extension` 目录）一致。

> 因为是以「已解压」方式加载的，扩展不会自动更新。拉取新代码后，回到扩展管理页点一下该扩展卡片上的「重新加载」即可。

## 使用

### 一、后台静默登录（推荐）

1. 点工具栏图标打开弹窗 → 点「设置」；
2. 填**学号**、**密码**；验证码识别服务选 `baidu`（填百度 API Key / Secret Key）或 `remote`（填自建接口地址）。**静默登录必须配 OCR，不配无法启动**；
3. 在「登录方式 · 后台请求」卡片里填**登录入口地址**：
   - 校外 / 走 WebVPN：复制你浏览器里 WebVPN 打开教务系统后的地址，形如
     `https://webvpn.<学校域名>/https-443/<一串 hex>/index.action`
   - 校内 / 直连：`https://jwgl.nxu.edu.cn`（`index.action` 可写可不写）
4. 设置间隔（默认 800 ms）与最多请求次数（默认 200），也可以勾上「浏览器启动后自动开始」；
5. 回到弹窗点**「开始后台请求登录」**。每次请求的进展会写进日志；成功后会自己打开已登录页面，并在日志里留下 `登录成功（第 N 次请求）`。

> **关于 WebVPN 的 hex 前缀**：那串 `77726476706e…` 是 WebVPN 每个会话生成的入口标识，不同会话可能不一样。扩展不会替你猜，请直接从浏览器地址栏复制当前可用的那一条 —— 这也是唯一可靠的办法。

> **关于请求频率**：百度 OCR 免费版限制 1 QPS。间隔设得太小（比如 200 ms）会连续撞限流，扩展会自动退避重试，但实际有效请求并不会变多。**建议间隔不低于 1000–1500 ms**。

### 二、页面自动填表

1. 点开弹窗 → 「设置」，填入学号密码，按需选择验证码方案（不确定就保持默认的人工输入），保存；
2. 打开 <https://jwgl.nxu.edu.cn>（或你配置的教务系统地址）；
3. 页面加载后会自动登录：右上角面板显示进度，需要输验证码时会弹出输入框，输完回车即可；也可以在弹窗里输验证码。

> 小提示：设置保存时会校验——比如开了「启用自动登录」却没填学号/密码、选了百度 OCR 却没填 Key、静默模式填了非法入口地址，都会在保存这一步直接拦下并提示。

**关于权限提示**：默认域名 `https://jwgl.nxu.edu.cn` 与 `https://webvpn.nxu.edu.cn` 的访问权限已在扩展里声明，安装时不会额外弹窗。只有你**在设置里添加了备用服务器地址**（比如你们校内的另一台教务主机）时，浏览器才会询问是否允许扩展访问该站点 —— 因为扩展需要在这个页面上注入填表脚本、并读取验证码图片。不授权的话，备用地址上的自动登录无法工作。

> ⚠️ **必须能访问教务系统**：教务系统只对校园网开放。校内直连 `jwgl.nxu.edu.cn`；校外请先用学校 WebVPN 打开一次教务系统，拿到带 `/https-443/<hex>/` 的地址再用。打不开页面时扩展也无能为力。

## 与原 Python 版的关系

| 维度 | 原 Python 版（`legacy/python/`） | Chrome 扩展版（`extension/`） |
| --- | --- | --- |
| 配置方式 | 直接改 `config.py` 源码里的 `username` / `password` / `API_KEY` / `SECRET_KEY` / `urls` | 扩展设置界面（存 `chrome.storage.local`），改完即时生效 |
| 运行环境 | Python 3 + 命令行 | Chrome 102+ / Edge，纯浏览器内运行 |
| 抢课姿势 | 后台死循环 POST，成功后自己 print | 「后台静默登录」模式：后台死循环请求，成功即带 Cookie 开页面 |
| 验证码方案 | 百度 OCR，失败后 `image.show()` 弹图人工输入 | 静默模式只用 OCR（`baidu` / `remote`）；页面模式还可人工输入 |
| Cookie 处理 | `requests.Session` 自己维护，需先 `GET /index.action` 拿 `JSESSIONID`，再取验证码、再 POST | 直接复用浏览器的 Cookie 罐（后台请求与页面共享会话），成功后打开的页面天然是登录态 |
| 依赖 | `requests`、`numpy`、`Pillow` 等（见 `requirements.txt`） | 无第三方依赖、无构建步骤 |
| 重试 | `login()` 内 `max_retry=5`，外层再遍历 `config.urls` | `captcha.maxAttempts` + `captcha.delayMs`，页面刷新后还能接着上次的进度计数 |

**原 Python 代码仍然可用**，完整保留在 `legacy/python/`：

```bash
cd legacy/python
pip install -r requirements.txt
copy config.example.py config.py     # Windows（Linux/macOS 用 cp）
# 编辑 config.py，填入 username / password / API_KEY / SECRET_KEY
python main.py
```

`config.py` 已加入 `.gitignore`，只存在于你本机，不会被提交。想了解扩展的内部设计，见 [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md)。

## 验证码方案的选择建议

| 方案 | 适合谁 | 说明 |
| --- | --- | --- |
| `manual` 人工输入（**默认，最稳**） | 页面模式下的所有人 | 面板里显示验证码图片，手动输入。识别率 100%，代价是每次登录点一下。**静默模式不支持。** |
| `baidu` 百度 OCR | 想全自动、愿意花几分钟申请 Key 的同学 | 需要自己到[百度智能云](https://cloud.baidu.com/product/ocr_general)开通「通用文字识别（高精度版）」，把 API Key / Secret Key 填进设置。有免费额度，超出按量计费。 |
| `remote` 自建 OCR 服务 | 有自己服务器的同学 | 扩展会把验证码图片以 dataURL 发给你的接口，取回识别文本。 |

> 实测（2026-10，真实站点 20 张验证码，用错密码排除干扰）：百度「通用文字识别」标准版 `general_basic` 准确率约 **60%**，高精度版 `accurate_basic` 约 **90%**。扩展固定走高精度版。即使 60% 的准确率，静默模式连打十几次也基本必中 —— 这正是「反复请求」的意义。

自建服务的请求格式（默认 `POST`，`Content-Type: application/json`）：

```json
{ "image": "data:image/png;base64,iVBORw0KGgoAAAANSUhEUg..." }
```

期望的响应：

```json
{ "result": "ab12" }
```

可在设置里调整三处：请求方法（GET / POST）、表单字段名（默认 `image`）、响应取值路径（默认 `result`，支持 `data.text` 这类嵌套路径、也支持数组下标）。GET 模式下图片会拼在查询串里。返回纯文本（非 JSON）也能识别；响应里只保留字母和数字。

## 安全与隐私

- **学号密码只在本机**：保存在 `chrome.storage.local`，属于扩展自己的沙箱存储，不会随网页请求发送，也不会同步到云端或上传到任何服务器。
- **百度 OCR 只上传验证码图片**：选择百度方案时，只有验证码那张小图（base64）会发往 `aip.baidubce.com`，学号密码不会离开本机。
- **自建服务由你自己负责**：`remote` 方案会把验证码图片发到你填的地址，接口的安全性和日志留存由你掌控。
- **公用电脑请注意**：用完建议在设置里清空学号密码，或直接移除扩展（移除会连同 `chrome.storage.local` 数据一起删掉）。
- 扩展申请的权限仅有：`storage`（存设置与状态）、`scripting`（给备用站点注入脚本）、`activeTab`、`notifications`（成功通知），以及对教务系统（含 WebVPN）与百度 OCR 的站点访问权限。

> ⚠️ **不要把自己的 Key 提交到仓库**：账号、密码、OCR 密钥一律只放在本机（扩展里是 `chrome.storage.local`，Python 版是 `legacy/python/config.py`）。本仓库的 `.gitignore` 已排除 `config.py`；提交前可以用 `git status` 确认它没有出现在变更列表里。历史里出现过的密钥无法靠删除文件消除，唯一可靠的处理是**到百度云控制台重新生成**。

## 常见问题

**Q1：密码填了，但打开页面没有自动登录？**
依次检查：① 设置里的「启用自动登录」开关是否打开；② 当前页面是否真的是登录页（有学号 + 密码输入框）；③ 是不是在已经登录的状态下打开的（那就不会重复登录）；④ 装完扩展后没刷新的旧标签页不会自动生效，按 F5 刷新一次；⑤ 面板上如果显示「请先在设置里填写学号与密码」，说明凭据没保存成功。

**Q2：验证码一直识别失败 / 一直重试？**
先换成人工输入方案（最稳）；人工输入时如果图看不清，点面板上的「看不清？换一张」；如果 OCR 方案总是错，检查百度 Key 是否有效、自建服务地址是否可达（设置页里点「测试识别服务」会立刻验证一次）。达到最大尝试次数后面板会停下并提示，不会无限刷。静默模式下「验证码不对」属于正常失败，会自动换图重来；如果日志里连续出现「识别未通过（识别结果过短）」，说明图片对 OCR 太难，换 `remote` 方案或提高间隔。

**Q2.1：静默登录一直失败，日志里是「仍停留在登录页」？**
说明 OCR 认出来的验证码被打回、或者站点响应变慢。先看日志里最后一次的分类：`captcha` 表示验证码错（继续等就行），`credentials` 表示账号密码被拒（已在第一次就停下，不会刷号），`unknown` 才需要排查 —— 多半是站点改版或网关报错。

**Q3：页面根本打不开？**
教务系统只对校内开放。校园内直接访问 `https://jwgl.nxu.edu.cn`；校外请先连学校 WebVPN，在浏览器里打开一次教务系统，把地址栏里形如 `https://webvpn.nxu.edu.cn/https-443/<hex>/index.action` 的地址复制进设置里的「登录入口地址」。hex 前缀每个会话可能不同，过期后重新复制一次即可。

**Q4：添加了备用地址，提示未授权 / 不工作？**
在设置里重新保存一次地址，浏览器会弹出权限询问，选择「允许」。若之前误点了拒绝，需要到 `chrome://extensions` → 本扩展「详细信息」→「网站访问权限」里手动放开，或删掉该地址重新添加。

**Q5：扩展更新 / 重新加载后，我的设置还在吗？**
在。设置存在 `chrome.storage.local`，重新加载扩展、重启浏览器都不会丢。只有在扩展管理页**移除**扩展时才会一并清空。

**Q6：面板挡住了页面内容？**
点面板右上角的 `×` 收起；也可以在设置里关掉「显示悬浮面板」。注意：关掉面板后就没法人工输验证码了，此时请配置 OCR 方案，或保持面板开启。
